title: "Creative strategy"
description: "Writing the brief each version exists to prove — the step that decides whether a test is readable."
---

Every version in a test needs a brief. The brief is not a creative wish-list; it is a statement of **what this arm is testing**, so that when the engine calls it you know what was proven.

## Draft the briefs

Briefs can be drafted for every version that does not have one yet, from the brand context and the test's goal. Review each one before generating anything.

A brief carries the **angle**, the **hooks**, and the **CTA** — the same unit of messaging the studios consume.

## One idea per version

This is the discipline the whole test depends on.

<Warning>
  If a version changes the angle *and* the persona *and* the format, a verdict tells you nothing. You will know the arm won or lost; you will not know which change did it, so you cannot iterate on it.

  Change one thing per version. Put executions of the same idea inside that version as variants.
</Warning>

The labels matter mechanically, not just editorially — the engine reads an arm's `angle`, `persona` and `format` labels and uses them when it recommends what to iterate on. An unlabelled arm produces vaguer recommendations.

## Write against evidence, not instinct

Before writing, read what the account already knows:

- **Patterns** — every ad in the account grouped by persona, awareness, angle and page, labelled against break-even
- **Learnings** — what previous tests and patterns have established, each one citable
- **Performance evidence** — the citation-tagged pack built for exactly this

<Tip>
  Cite the learning or pattern a brief is built on. When the test concludes, a reader can follow the chain from verdict back to the reasoning — and a brief that contradicts an existing learning becomes visible before it spends money rather than after.
</Tip>

## Where the brief comes from

Three routes, same output:

| Route | Use it when |
| --- | --- |
| **Generated** | The usual path — written from brand context and the test goal |
| **Uploaded** | The brief already exists as a document |
| **Reference ad** | You are working from an ad that already performs |

## Layout is a separate decision

Briefs do not need to invent a layout. The blueprint library ranks templates for the brand; attaching one to a brief makes generation compose inside that structure rather than improvising.

<Note>
  Using a brief to generate is the sign-off. There is no separate approval gate — generating from a brief marks it approved. Signing one off ahead of production, or rejecting one, is a deliberate separate action.
</Note>
