A Skill is a house procedure written down so the product can run it. They exist so expertise lives in the product rather than in one person's head.

Before solving a recurring task from scratch, check whether someone already wrote it down.

## What's live

| Skill | What it does |
| --- | --- |
| **meta-account-audit** | Read-only diagnostic of a Meta ad account. Scores Signal, Structure, Waste and Creative, and ranks the top actions |
| **daily-pulse** | The recurring account report, from Meta performance, Slack and ClickUp. Scores Activity, Efficiency, Creative and Coverage |
| **meta-ad-copywriter** | Primary text and headline for creatives about to publish. Varies the batch so ads in one ad set aren't paraphrases |
| **long-form-static-creator** | A 600–2,000 word direct-response static — advertorial or listicle style |
| **ad-image-director** | Creative direction for a single static image. Returns a plan, not an image |

All five are read-only or produce drafts. None of them spend money or change an account.

<Note>
  **meta-ad-copywriter** writes short ads. **long-form-static-creator** writes long ones. Picking the wrong one produces copy in the wrong register for the placement.
</Note>

## Running one

Run a Skill by name against a brand. Some take inputs — a product, a template, a lookback window — and you'll be asked for what's missing.

A Skill runs unpinned only if it's **live**. Drafts run only for the agency owner or an admin, which is how an unfinished procedure stays out of general use.

## Writing your own

A skill is a **single task**: one person or system, one sitting, one clear output, nobody approving anything partway through.

If it takes days, involves handoffs, or needs someone to sign off in the middle, it's a **process** — write it as an SOP instead.

<Tip>
  The test: *can one person do this in one sitting and end up with one thing, with nobody approving anything partway through?* Yes means skill. No means process.
</Tip>

## The library

Procedures are kept in the [Kommerce library](https://github.com/kommerce-ai/kommerce-library) as plain markdown, organised by job: meta audit, angle and competitor research, creative generation, media buying, reporting.

Each job folder holds `skills/` for single tasks, `sops/` for multi-step processes, and `processes/` for maps of how something works before it's been turned into either.

Anything you've built elsewhere can be brought in by pull request.
